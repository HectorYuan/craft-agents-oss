### 本版主题：MCP 启动链修复 + 用户文案去「域」+ 发版链把 Windows 内嵌 CPython 保住

★ 本版解决三类「装上了却用不了」的问题：打包版的 MCP 服务起不来、工具注册表是旧引擎、
以及构建脚本会把 Windows 离线首跑依赖删掉。

#### 修复

- **打包版 MCP 服务启动失败（Permission denied）**：打包把 `resources/zenskill` 设为只读，
  而启动配置走 `uv run --project <pack>` ⇒ uv 要在该目录建临时文件 ⇒ `Permission denied` ⇒
  uv 秒退 ⇒ 客户端报 `-32000 Connection closed`。改为**优先直连预建 venv 的解释器**
  （`resolveVenvPython` / `buildLaunchSpec`），并让**已装用户**下次启动自动升级到 venv 形态
  （`applyZenskillSelfHeal` 增加「uv 启动 → venv 直连」路径，同时清掉 `env.UV_PROJECT_ENVIRONMENT`）。
  Windows 侧同步改 `zenskill-cmd.cmd` 与 agent backend 的 venv 探测。
- **MCP 工具注册表停在旧引擎（`Unknown tool: attention_status`）**：`bun run electron:dist:dev:mac`
  这条链**不执行**主仓 `copy_zenskill()` ⇒ 包内引擎恒为 vendor 里的旧版本（0.9.12）。
  改用主仓脚本重打包后，服务端工具数 **100 → 113**，`attention_status` 正常注册并返回真实读数。
- **构建脚本会删掉 vendor 的 Windows 内嵌 CPython**：`copy_zenskill()` 用 `rm -rf` 清空目标目录，
  把 git 跟踪的 `cpython-3.12.14-windows-x86_64-none`（58MB / 2776 文件）一并删除 ⇒ 打一次 mac 包
  后 vendor 工作树脏 2954 项、Windows 离线首跑运行时丢失。改为**构建前 `mv` 到临时目录暂存、
  复制完成后再归还**（同盘 mv 零拷贝），Windows 与 macOS 两套 CPython 并存。
  配套修 `check-release-precommit.sh` 八项门禁全过。

#### 变更

- **用户界面不再出现「域」字样**：域是内部业务概念，不对用户呈现。修炼页标题 `修炼域` → `修炼`，
  两处提示文案去掉「域」（`去「项目」看待办` / `任务和行动项在「项目」`）。侧栏分组仍是
  会话 / 项目 / 技能 / 今日 / 设置 五组。
