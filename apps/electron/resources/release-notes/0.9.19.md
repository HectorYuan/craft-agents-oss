### ⚠️ 本版补上 v0.9.18 缺的 Windows NSIS 安装包

★ **v0.9.18 未能带出 Windows NSIS 安装包**（v0.9.16 / v0.9.17 同样没有）⇒ 根因在
2026-10-26 从 **Windows 腿的作业日志逐 step 读出**（run `40323011860` / job
`121616031731`：13:59:59Z 起、14:42:58Z 止，**整条腿只用了 42 分 59 秒，并未超
45 分钟预算** ⇒ 它是**自己挂的**，不是被超时砍掉的）——**两层病因叠在一起**：

**第一层 · 门禁白等 40 分钟**：日志里那句
`##[error]CI not green within 40min (runs: {"message":"Resource not accessible by
integration",...,"status":"403"})` 是决定性证据 —— `release.yml` 的 `permissions`
只有 `contents: write` ⇒ 门禁的 `gh api actions/runs` 返回 **403** ⇒ 403 的 JSON
**错误体**被门禁的 `decide()` 当成「有 run 还在跑」⇒ 判成 wait ⇒ 白等
`GATE_WAIT_SECONDS=2400` ⇒ 这一步就吃掉 **40 分 03 秒**。

**第二层 · 同步成功了却被判红（假红）**：门禁放行后只剩 2 分半，官方构建 1 分 33 秒
+ Stage native binaries 49 秒，剩下 **0 秒**给「同步引擎源码」这一步；而它**其实
成功了**——日志里 `engine source synced -> …\resources\zenskill` 已打印，20 毫秒后
才 `##[error]Process completed with exit code 1.` ⇒ 步骤被判 FAILED ⇒ 第 8–11 步
（electron-builder NSIS / Smoke / 展平 / 直传）**全 skipped** ⇒ **`.exe` 出不来**。

★ **第二层的机理**（此前连续三版都没人读到这里）：runner 的 `shell: powershell`
处理器会在临时 `.ps1` **末尾追加**
`if ((Test-Path -LiteralPath variable:\LASTEXITCODE)) { exit $LASTEXITCODE }`
⇒ **脚本里最后一个原生命令的退出码 = 步骤退出码**；而 `robocopy` **复制成功时返回 1**
（robocopy 语义里的**成功码**）⇒ 同步完全正确、步骤却被判红。

四处修复：

1. **`permissions` 补 `actions: read`**（第一层根因）——门禁要读 `actions/runs` 判定
   「本 commit 的 CI 是否绿」，没这个权限就**读不到**。
2. **`gate-check.sh` 的 `decide()` 增加负载形态校验**：只接受 `status:conclusion`；
   403/404/5xx 的错误体判 **malformed** ⇒ **fail-fast 并说清原因**，不再被当成
   「还在跑」白等 40 分钟。附 2 条负控（403 / 404 两种错误体）。
   ★ 与「哨兵值 0 与空值不可混用」同款纪律：**探测失败必须与真实读数可区分**。
3. **`windows-local` 的 `timeout-minutes` 45 → 90**（结构性预算对齐）：门禁可以
   **合法地**等 CI 跑完（本仓 CI 一轮 40~50 分钟），job 预算必须容得下
   「门禁等待 + 真实工作」两段，否则门禁等满就必然没有时间打包。
4. **Windows 腿 4 处 PowerShell 步骤显式 `exit 0` 收尾**（第二层根因）：把退出码
   变成**显式声明**，不再由最后一个原生命令泄漏决定。

★ 新守卫三条（各自自带负控）：**R10** = `release.yml` 的 permissions 必须含
`actions: read`（删掉即报红）⇒ 防「谁把权限删了 ⇒ 又是连续三版没有 `.exe`」；
**R11** = 发布腿预算必须容得下「门禁等待 + 真实工作」两段；**R12** = Windows 腿
PowerShell 步骤**末行必须显式 `exit`**（判据是「末行必须显式 exit」，不是
「用了 robocopy」）⇒ 防假红复发。

### ⚠️ 补记：首次发版的 `.exe` 是**补传**的（那次 tag 流水线撞上了第三层病因）

★ 上面四处修复在 2026-10-26 进了 `main`，但它们是在 **v0.9.19 的 tag 打好之后**
才落地的 ⇒ **tag 指向的那个提交**里，`release.yml`（含 Smoke 的镜像断言）
**还没有第三层修复**
⇒ v0.9.19 自己的 Windows 腿重跑时撞上了**第三层病因**（前三版都没暴露过）：
⇒ 该 tag 里的同步步仍是旧语义 ⇒ **正式路径出不来 `.exe`**。
⇒ **口径（2026-10-27 用户拍板）：`v0.9.19` 的 tag 重指到含第三层修复的提交**，
并重跑正式的 `release.yml` ⇒ 使「tag 推送 ⇒ 正式路径自动出包」这条链**第一次被真机验证**。
（首次发版时该 tag 指向的提交还没有第三层修复 ⇒ 那一次是靠补传落地的，见下文如实披露。）

**第三层 · 载荷里多了一颗陈旧文件 ⇒ 镜像断言判 extra ⇒ 假红**：同步步用
`robocopy /MIR /XD … webui` 把引擎源码镜像进载荷，但 **robocopy 的 `/XD` 排除在
目标侧同样生效** ⇒ 被排除的目录在目标里**不会被 `/MIR` 清掉** ⇒ 上游 0.13.3 版
桌面应用遗留的构建元数据 `resources/zenskill/webui/build_meta.json`
（`craft_version 0.13.3` / `built_at 2026-09-20`）在主仓 `zenskill/` 早已不存在，
却仍被打进安装包 ⇒ 冒烟步的镜像判定 `robocopy /MIR /L` 判 **exit 2（extra）**
⇒ 冒烟红 ⇒ 展平与直传两步 skipped ⇒ **`.exe` 依旧出不来**。
★ 这次**之所以查得出来**，是因为冒烟步把 robocopy 的输出 `| Out-Null` 吞掉、
`/NFL /NDL` 又抑制了清单 ⇒ 日志里只剩一句 `robocopy 2`，**多余项一个都看不见**
⇒ 只能另写一个临时诊断 workflow 上真机逐个 robocopy 变体比对，才定位到那一颗文件。

★ **首次发版时 `.exe` 的来历（如实披露）**：那次 tag 流水线走不通 ⇒ 改用**已构建产物补传**：
`ZenSkill-x64.exe`（`ProductVersion 0.9.19` / `FileVersion 0.9.19`，构建于
2026-10-26T17:43:18Z，213,022,956 字节，
SHA256 `93ffee04904b5b2e81f58ffc94b593cb8663217b5312a86bc9c65e4bd9e4fd3a`）
由一次性诊断 workflow 上传；上传后**反查资产清单**、size 与本地产物一致才算数。
⇒ **本版的 `.exe` 不是该 tag 的流水线自动产出的**，而是同一台 Windows runner 上、
同一份 v0.9.19 源码构建出来的产物。
（补传前已核过：镜像判定的 **bit0 = 0** ⇒ 包内引擎文件与仓库**逐字节一致**，
引擎版本 0.9.19，冒烟的前 5 道断言全过 ⇒ 唯一多余项就是那颗无人引用的陈旧元数据。）
★ **本版（重指并重跑正式流水线后）的 `.exe` 由该 tag 自己的流水线产出** —— 下面这段
记的是**首次发版**的历史过程，不是最终交付物的来历。

★ **根因修复**（已入 `main`，并随本次 **v0.9.19 的 tag 重指**一并生效）：

1. **同步步改「先清空载荷子树，再整树复制」**（= Linux 腿 `rm -rf` + `rsync` 的
   同口径）⇒ 目标树必然是源树的子集，陈旧内容无处可藏。
2. **冒烟步的镜像判定失败时必须打出差异清单**（不再 `Out-Null` 吞输出）。
3. **新守卫 R13**：镜像判定必须做**两遍**（静默判定 + 失败时带清单的明细），
   且明细那遍**不得**被 `Out-Null` 吞掉。
   （守卫 R9 同步改判据：同步步必须**先清空**复制目标 —— 旧的「用 `/MIR` 即可」
   判据拦不住「`/XD` 在目标侧不清理」这件事。）

★ 真机 A/B 验证（run `40373706047`，同一台 runner、同一份源树）：
`OLD-PATH`（对着带陈旧文件的真载荷做 `/MIR /L`）= **exit 2**；
`NEW-SYNC`（先清空再 `/E` 整树复制）= **exit 1**（已复制）；
`NEW-PATH`（对新载荷做 `/MIR /L`）= **exit 0（逐字节一致）**
