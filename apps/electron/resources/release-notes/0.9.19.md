### ⚠️ 本版补上 v0.9.18 缺的 Windows NSIS 安装包

★ **v0.9.18 未能带出 Windows NSIS 安装包**（v0.9.16 / v0.9.17 同样没有）⇒ 根因在
2026-10-26 从 **Windows 腿的作业日志逐 step 读出**（run `40323011860` / job
`121616031731`：13:59:59Z 起、14:42:58Z 止，**整条腿只用了 42 分 59 秒，并未超
45 分钟预算** ⇒ 它是**自己挂的**，不是被超时砍掉的）——**两层病因叠在一起**：

**第一层 · 门禁白等 40 分钟**：日志里那句
`##[error]CI not green within 40min (runs: {"message":"Resource not accessible by
integration",...,"status":"403"})` 是决定性证据 —— `release.yml` 的 `permissions`
只有 `contents: write` ⇒ 门禁的 `gh api actions/runs` 返回 **403** ⇒ 403 的 JSON
**错误体**被门禁的 `decide()` 当成「有 run 还在跑」⇒ 判成 wait ⇒ 白等
`GATE_WAIT_SECONDS=2400` ⇒ 这一步就吃掉 **40 分 03 秒**。

**第二层 · 同步成功了却被判红（假红）**：门禁放行后只剩 2 分半，官方构建 1 分 33 秒
+ Stage native binaries 49 秒，剩下 **0 秒**给「同步引擎源码」这一步；而它**其实
成功了**——日志里 `engine source synced -> …\resources\zenskill` 已打印，20 毫秒后
才 `##[error]Process completed with exit code 1.` ⇒ 步骤被判 FAILED ⇒ 第 8–11 步
（electron-builder NSIS / Smoke / 展平 / 直传）**全 skipped** ⇒ **`.exe` 出不来**。

★ **第二层的机理**（此前连续三版都没人读到这里）：runner 的 `shell: powershell`
处理器会在临时 `.ps1` **末尾追加**
`if ((Test-Path -LiteralPath variable:\LASTEXITCODE)) { exit $LASTEXITCODE }`
⇒ **脚本里最后一个原生命令的退出码 = 步骤退出码**；而 `robocopy` **复制成功时返回 1**
（robocopy 语义里的**成功码**）⇒ 同步完全正确、步骤却被判红。

四处修复：

1. **`permissions` 补 `actions: read`**（第一层根因）——门禁要读 `actions/runs` 判定
   「本 commit 的 CI 是否绿」，没这个权限就**读不到**。
2. **`gate-check.sh` 的 `decide()` 增加负载形态校验**：只接受 `status:conclusion`；
   403/404/5xx 的错误体判 **malformed** ⇒ **fail-fast 并说清原因**，不再被当成
   「还在跑」白等 40 分钟。附 2 条负控（403 / 404 两种错误体）。
   ★ 与「哨兵值 0 与空值不可混用」同款纪律：**探测失败必须与真实读数可区分**。
3. **`windows-local` 的 `timeout-minutes` 45 → 90**（结构性预算对齐）：门禁可以
   **合法地**等 CI 跑完（本仓 CI 一轮 40~50 分钟），job 预算必须容得下
   「门禁等待 + 真实工作」两段，否则门禁等满就必然没有时间打包。
4. **Windows 腿 4 处 PowerShell 步骤显式 `exit 0` 收尾**（第二层根因）：把退出码
   变成**显式声明**，不再由最后一个原生命令泄漏决定。

★ 新守卫三条（各自自带负控）：**R10** = `release.yml` 的 permissions 必须含
`actions: read`（删掉即报红）⇒ 防「谁把权限删了 ⇒ 又是连续三版没有 `.exe`」；
**R11** = 发布腿预算必须容得下「门禁等待 + 真实工作」两段；**R12** = Windows 腿
PowerShell 步骤**末行必须显式 `exit`**（判据是「末行必须显式 exit」，不是
「用了 robocopy」）⇒ 防假红复发。
