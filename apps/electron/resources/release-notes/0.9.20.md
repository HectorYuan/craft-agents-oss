### 本版主题：界面文案进 locale 真相源 + 读数口径归位 + 协作机制 v2 与多端同步引擎

#### 新增

- **协作机制 v2**：真相源 YAML + 事件日志 + 看板生成物 + 7 条门禁（含负控自证）。
  基准改为「不存值、只存怎么验证」⇒ 当场抓到旧台账里已过期的 vendor 指针。
- **多端同步引擎**：记录级三方合并 + 字段级合并 + 墓碑删除传播，
  Git / 目录 / 导入包三通道；覆盖 GTD、记忆、目标、成长四域。
- **技能域接成长契约读数条**：等级 / 里程碑 / 使用记录。
- **个体模型页加「误差范围 ±X 分」读数**（第四种量纲收尾）。
- **项目域读数接进 craft 项目页**：「项目路径 ↔ 项目实体」整合。

#### 变更

- **用户可见界面文案迁进 locale**：tooltip / toast 第一批，记忆页第二批。
- **维度名两套 key 收敛成一套**（记忆页不再两套命名并存）。
- **语义色归位**：集中到一张表 + 默认色清零。
- **动态分类色的双模**：亮色加深版 + 单一色值处。
- **量纲纪律文案真相源化**：「两种单位不可相加：能量是燃料，注意力是闸门」不再硬编码在代码里。
- **读数文案改名 `errorRange`** —— 与「五态错误文案」区分，避免同形异义。

#### 修复

- **项目域读数三处真缺陷**：进度条恒满 / 排序无口径。
- **审计轨迹读取改按事件轮询** ⇒ 修 `lease-store-cap` 用例的间歇红。

#### 工程与发版链

（不面向终端用户，但决定后续版本能不能按时、可验证地交付）

- 门禁 **G-13** 白名单从「文件级」收窄为「文件 + 允许形态」，判据覆盖 CSS。
- 新增门禁 **G-14「真相源文案副本检测」** ⇒ 堵上真相源纪律的第三个盲区。
- 治理 runner 磁盘满导致的 Python 腿假红（A/B/C/D 四案，治本 + 兜底 + 门禁）。

- `detect-win` 迁到 Windows runner ⇒ 解除「Windows 产物链路依赖 Linux 机」的结构性耦合。
- 版本派生脚本自行探测解释器（Windows runner 上没有可用的 `python3`）。
- 修 PS 5.1 编码缺陷：文本读取显式 `-Encoding UTF8`。
- 发版链的「CI 绿」门禁改硬并抽成独立 blocking `gate-ci` job；等待预算与 job 预算对齐。

#### 已知限制

- **本版只随附 macOS 安装包**（dmg / zip）。Windows NSIS 与 Linux 三件套本次未产出。
- 因此本次发布**没有 CI 绿证据**，已在协作台账显式登记。
- **Windows `.exe` 本次刻意未用「自测逃生阀」绕过门禁产出**：该逃生阀自述
  「tag 发版路径无法绕过」，用它出正式产物与其语义相悖 ⇒ 留待构建机恢复后按标准流程补出。

> ★ **归因订正（2026-10-30，v0.9.21 发布时补记）**：本段原写「自托管 Linux 构建机 `zenskill-build-2`
> 处于离线状态」是**误判** —— 该机当时**在线**（`GET /actions/runners` 连续采样三次均 online/busy）。
> 真实原因是**两道**：(1) **队列占位** —— 08:47Z 的旧 sha 轮一直占着唯一那台 Linux runner，
> 把本 sha 的 CI 轮压成 0 个 job；(2) **门禁在 CI 里不可复现** —— 协作状态门禁因「检出无 tag」与
> 「看板抄了易变读数」而恒红 ⇒ **tag 的 sha 结构性拿不到绿证据**。
> ⇒ 两者都已修（见 v0.9.21）⇒ **「本地门禁全绿」不等于「CI 能绿」**：判据若依赖检出形态，
> 本地与 CI 就会给出相反结论。
